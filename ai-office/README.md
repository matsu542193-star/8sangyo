# 🐝 蜂の巣駆除産業|AIオフィス

社内用の統合Webアプリ(組織ポータル + 請求書管理)。
Vite + React(SPA)、Tailwind CSSでスタイリング。データはブラウザ内(localStorage / IndexedDB)にのみ保存され、外部サーバーには送信されません(AI-OCR機能を除く)。

## 起動手順

```bash
cd ai-office
npm install
cp .env.local.example .env.local   # 作成後、下記の環境変数を設定
npm run dev
```

`http://localhost:5173/` (または表示されたポート) にアクセスし、スマホでの確認は同じWi-Fi内の別端末から `npm run dev -- --host` で起動してアクセスしてください。

## 環境変数(`.env.local`)

`.env.local` はコミットしないでください(`.gitignore` 済み)。

| 変数 | 用途 |
|------|------|
| `VITE_APP_PASSWORD` | パスワードゲートの合言葉(初回アクセス時に要求) |
| `VITE_ANTHROPIC_API_KEY` | 「請求」→「読取」タブのAI-OCR(請求書画像読み取り)で使用するAnthropic APIキー |

`VITE_ANTHROPIC_API_KEY` を設定しない場合、他のタブ(組織/部署/週間/投稿/請求の一覧・作成・写真)は問題なく使えますが、「読取」タブは動作しません。

## ⚠️ 重要な注意点

- **本アプリは社外非公開です。** ビルド成果物やソースを外部に公開・デプロイする場合は、パスワードゲートがブラウザのJSに含まれるだけの簡易的な保護であること、`VITE_ANTHROPIC_API_KEY` がクライアント側バンドルに埋め込まれる(=ビルドファイルを解析すれば読み取れる)ことを理解した上で行ってください。
- **APIキー入りのビルドをそのまま公開しないこと。** Vercel等にデプロイする場合は、APIキーが漏れない構成(サーバー経由のプロキシ等)を別途検討することを推奨します。今回はローカル利用(`npm run dev`)を前提にしており、簡易デプロイの手順とリスクは下記に記載します。
- データ(請求書・チェック状態・写真)はすべて**その端末のブラウザ内**に保存されます。ブラウザのデータを消去する・別端末やシークレットモードで開くと引き継がれません。バックアップの仕組みは今回未実装です。

## Vercel等へ非公開デプロイする場合の手順とリスク

1. `vercel` などにデプロイすると、URLを知っている人は誰でもアクセス可能になります。パスワードゲートはあくまで簡易的なものです(ブラウザの開発者ツールで回避可能)。社外に絶対見せたくない場合は、Vercelの「Password Protection」機能(有料プラン)や、Basic認証をエッジ側で追加することを推奨します。
2. 環境変数(`VITE_APP_PASSWORD` / `VITE_ANTHROPIC_API_KEY`)はVercelのプロジェクト設定 → Environment Variablesで設定してください。ビルド時に埋め込まれるため、**ブラウザ側から値を読み取ることが可能**です。特にAnthropic APIキーは第三者に使われる(課金される)リスクがあるため、利用量アラートの設定を強く推奨します。
3. デプロイコマンド例:`vercel --prod`(事前に `vercel login`)。ビルドコマンドは `npm run build`、出力ディレクトリは `dist`。

## 質問リスト・不明点(仕様を変更せずTODOとして残した点)

同梱キットの `data/portal_data.json` が **空ファイル** だったため、`src/data/portalData.js` は各部署マニュアル(00〜06)・`gbp_posts_week_0713.md` から手動で復元しました。以下、判断した点と確認をお願いしたい点です。

1. **部署タブの件数**:指示書では「タブ1は6部署グリッド」「タブ2は7部署アコーディオン」となっていたため、`depts` に秘書AIを含む7件を定義し、タブ1では秘書AIを除いた6件のみグリッド表示しています。この解釈で問題ないか確認をお願いします。
2. **週間ルーティンの「毎日」「月末」タスクの割り当て**:00番の指示文にある「毎日」の項目(事務部LINE対応・SNS部Threads投稿)は月〜日の全曜日に複製し、「月末」の財務部タスクは便宜上「月」に「(月末のみ)」と注記して含めました。曜日別チェックリストという要件上、月末専用の見せ方(例:月末のみ表示する特別セクション)が必要であれば追加実装します。
3. **請求書と写真の紐付け経路**:仕様の「作成」フォームには写真アップロード欄の指定がなかったため、原本写真の紐付けは「読取(AI-OCR)」タブの「原本写真も紐付けて保存」チェックからのみ行える実装にしています。手動作成した請求書に後から「写真」タブの写真を紐付けたい場合の動線は未実装です。必要であれば追加します。
4. **AI-OCRのモデル名**:指示書の指定通り `claude-sonnet-4-6` を使用しています。実際にAPIキーで動作確認した際にモデル名エラーが出る場合は `src/lib/ocr.js` の `MODEL` 定数を調整してください。
5. **PWAのオフライン対応**:`manifest.json`とアイコンを用意し「ホーム画面に追加」は可能ですが、Service Workerによるオフラインキャッシュは指示書に明記がなかったため未実装です(オンライン前提)。
6. **請求書番号の採番**:`8S-{西暦}-{0001から連番}` は年ごとにリセットされる連番としています(localStorageで年別に管理)。年をまたいでも連番を継続したい場合は仕様変更が必要です。
